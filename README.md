# Image Metadata Reader

> Веб-приложение для побайтового анализа метаданных изображений без сторонних библиотек.  
> Форматы: **JPEG · PNG · BMP · GIF · TIFF · PCX**

🌐 **[Открыть приложение](https://YOUR-USERNAME.github.io/Lab2/)**

## Возможности

| Функция | Описание |
|---|---|
| 🔬 Ручной парсинг байтов | Полностью ручной разбор заголовков по спецификациям форматов |
| ⚡ Lazy Loading | Читаются только первые 64 KB файла — файл целиком не грузится |
| 🔀 Многопоточность | Web Workers для параллельной обработки (N−1 ядер CPU) |
| 📊 До 100 000 файлов | Батчевая обработка по 64 файла за раз |
| 🔍 Детекция подмены | Определяет реальный формат по сигнатуре, не по расширению |
| ⚠️ Битые файлы | PNG без IEND, JPEG без EOI, BMP с неверным размером |
| 📤 Экспорт CSV | Выгрузка всех результатов в CSV с BOM для Excel |
| 🎨 Тёмная/светлая тема | Переключатель темы с сохранением преференции |

## Способ извлечения данных

### Принцип работы

1. **Lazy Read:** от каждого файла читается **только первые 64 KB** через `File.slice(0, 65536)` + `FileReader.readAsArrayBuffer()`. Это позволяет обрабатывать 2 ГБ папок за секунды.

2. **Web Worker Pool:** создаётся `navigator.hardwareConcurrency − 1` воркеров. Файлы распределяются батчами по 64 штуки. `ArrayBuffer` передаётся через `Transferable` — без копирования памяти.

3. **Парсинг в воркере:** каждый воркер вызывает `parseImageFile()` из `parsers.js`, которая:
   - определяет реальный формат по **Magic Numbers** (сигнатуре)
   - вызывает нужный парсер
   - возвращает структурированный объект метаданных

## Форматы и источники данных

### JPEG
**Спецификация:** ISO/IEC 10918-1 (JFIF 1.02)

| Данные | Источник | Смещение/маркер |
|---|---|---|
| Ширина, высота | SOF0/SOF1/SOF2 маркер (`FF C0`..`FF C2`) | +3/+1 от начала данных сегмента |
| DPI | APP0 (JFIF, `FF E0`) | bytes 7–10: XDensity, YDensity |
| DPI (EXIF) | APP1 (`FF E1`), IFD теги 0x011A/0x011B | RATIONAL (числитель/знаменатель) |
| Глубина цвета | precision × components из SOF | precision[1] × nComponents[1] |
| Тип сжатия | Маркер SOF: C0=Baseline, C2=Progressive | код маркера |
| Матрица квантования | DQT (`FF DB`) | 64 значения 8- или 16-bit |
| Валидность | EOI маркер `FF D9` в конце файла | последние 2 байта |

### PNG
**Спецификация:** RFC 2083 / ISO/IEC 15948

| Данные | Источник | Смещение |
|---|---|---|
| Сигнатура | `89 50 4E 47 0D 0A 1A 0A` | байты 0–7 |
| Ширина, высота | Чанк IHDR, байты 0–7 данных | +16, +20 от начала файла |
| Глубина цвета | bitDepth × channels из colorType | байты 24–25 |
| DPI | Чанк pHYs: pxPerUnitX × 0.0254 | при unit=1 (метры) |
| Чересстрочность | InterlaceMethod в IHDR | байт 28: 0=нет, 1=Adam7 |
| Валидность | Наличие чанка IEND в конце | последние 12 байт |

### BMP
**Спецификация:** Microsoft BITMAPFILEHEADER + BITMAPINFOHEADER

| Данные | Источник | Смещение |
|---|---|---|
| Сигнатура | `42 4D` ("BM") | байты 0–1 |
| Ширина | biWidth | +18 (4 байта LE) |
| Высота | biHeight (знаковое; < 0 → top-down) | +22 |
| DPI | biXPelsPerMeter × 0.0254 | +38/+42 |
| Глубина цвета | biBitCount | +28 |
| Тип сжатия | biCompression: 0=RGB, 1=RLE8, 2=RLE4 | +30 |
| Палитра | clrUsed или 2^biBitCount при ≤8 bpp | +46 |

### GIF
**Спецификация:** GIF87a / GIF89a (CompuServe)

| Данные | Источник | Смещение |
|---|---|---|
| Сигнатура | `GIF87a` или `GIF89a` | байты 0–5 |
| Ширина, высота | Logical Screen Descriptor | +6, +8 (2 байта LE) |
| Глубина цвета | SizeOfGCT + 1 (из packed byte) | байт 10, биты 0–2 |
| Цветов в палитре | 2^(SizeOfGCT+1) | из packed byte |
| Анимация | Подсчёт Image Descriptor блоков (0x2C) | сканирование блоков |
| Валидность | Trailer байт `3B` в конце | последний байт |

### TIFF
**Спецификация:** Adobe TIFF 6.0

| Данные | Источник | Теги IFD |
|---|---|---|
| Ширина | Tag 256 (0x100) | SHORT или LONG |
| Высота | Tag 257 (0x101) | SHORT или LONG |
| DPI | Tags 282/283 (RATIONAL) + Tag 296 (ResolutionUnit) | unit=2→DPI, 3→DPCM |
| Глубина цвета | Tag 258 × Tag 277 (BitsPerSample × SamplesPerPixel) | |
| Тип сжатия | Tag 259: 1=нет, 5=LZW, 6=JPEG, 32773=PackBits | |
| Цветовая модель | Tag 262 (PhotometricInterpretation) | 2=RGB, 5=CMYK, 3=Palette |

### PCX
**Спецификация:** ZSoft PCX Format Technical Reference

| Данные | Источник | Смещение |
|---|---|---|
| Сигнатура | `0x0A` | байт 0 |
| Ширина | XMax − XMin + 1 | +8, +4 (2 байта LE) |
| Высота | YMax − YMin + 1 | +10, +6 |
| DPI | HDpi, VDpi | +12, +14 |
| Глубина цвета | BitsPerPixel × NPlanes | +3, +65 |
| Сжатие | Encoding: 1=RLE (PackBits) | байт 2 |
| Палитра VGA | 256 цветов × 3 байта в конце файла, предваряется `0x0C` | -769 от конца |

## Производительность

| Параметр | Значение |
|---|---|
| Читается байт на файл | ≤ 65 536 (первые 64 KB) |
| Воркеров | `navigator.hardwareConcurrency − 1` |
| Батч | 64 файла/воркер/итерация |
| Передача буферов | `Transferable` (zero-copy) |
| Целевая скорость | > 500 файлов/с на SSD |

## Сторонние библиотеки

**Не используются** для чтения метаданных.

Использован только браузерный API:
- `FileReader.readAsArrayBuffer()` — чтение байтов
- `File.slice()` — чтение только заголовка
- `Worker` — многопоточность
- `URL.createObjectURL()` — экспорт CSV
